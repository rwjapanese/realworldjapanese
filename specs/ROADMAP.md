## Parallel-work rules (read before running builds)

複数セッションを並列で動かす運用なので、フェーズごとに並列可否を分ける:

- **執筆（mdx / spec の作成・編集）= 並列OK。**
- **`pnpm astro check`（型・content schema 検証）= 並列OK。** 記事単位の検証はこれを既定にする（OG画像のチャンク生成をしない＝競合しない）。
- **`astro build`（フルビルド）= 直列。pnpm 固定（`npm` 混在禁止 — lockfile は `pnpm-lock.yaml` のみ）。** `pnpm build` は `scripts/build-lock.sh` 経由でアトミックロックがかかり、同時実行は自動で1本に直列化される（2本目は待機）。フルビルドは「最終確認1回」だけにする。
- **落ちた時のクリーン**: まず `rm -rf .astro`（content-layer キャッシュのみ）。効かなければ `rm -rf .astro dist node_modules/.vite`。**`node_modules` 本体は消さない**（再 install で遅くなるだけ）。
- 真の並列ビルドが必要なら `git worktree` でセッションを物理隔離する。

背景は §"Recent decisions" 2026-06-03「並列ビルド競合の恒久対策」。

## Session auto-loading (no manual handoff needed)

This repo ships `AGENTS.md` + `.cursor/rules/roadmap-workflow.mdc` at the root,
which Cursor and Claude Code auto-read every session. Those files instruct the
agent to:

1. Read this ROADMAP.md before responding.
2. Update it when tasks complete (tick checkboxes, log decisions, queue new
   TODOs).

So the user does **not** need to paste any handoff phrase. Just open the repo
and start working.

If you ever need to override that behavior in a specific chat, paste:

> Read `specs/ROADMAP.md` and pick up from the P0 section. After any task,
> tick the TODO and log under "Recent decisions".
